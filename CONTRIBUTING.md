# Contributing to Flowlog

First off, thank you for considering contributing to Flowlog! It's people like you that make Flowlog such a great tool.

## How Can I Contribute?

### Reporting Bugs

This section guides you through submitting a bug report for Flowlog. Following these guidelines helps maintainers and contributors understand your report, reproduce the behavior, and find related reports.

- **Check if the bug has already been reported** by searching on the GitHub Issues page.
- **Use a clear and descriptive title** for the issue to identify the problem.
- **Describe the exact steps which reproduce the problem** in as many details as possible.
- **Describe the behavior you observed after following the steps** and point out what exactly is the problem with that behavior.
- **Explain which behavior you expected to see instead and why.**

### Suggesting Enhancements

This section guides you through submitting an enhancement suggestion for Flowlog, including completely new features and minor improvements to existing functionality.

- **Check if there's already an issue for the enhancement**.
- **Use a clear and descriptive title**.
- **Provide a step-by-step description of the suggested enhancement** in as many details as possible.
- **Provide specific examples to demonstrate the steps**.
- **Describe the current behavior and explain which behavior you expected to see instead** and why.

### Pull Requests

The process described here has several goals:
- Maintain Flowlog's quality
- Fix bugs and deliver features faster
- Limit unnecessary work

Please follow these steps to have your contribution considered by the maintainers:

1.  **Fork the repository** and create your branch from `main`.
2.  **Ensure that you use `bun`** for dependency management.
3.  **If you've added code that should be tested, add tests**.
4.  **If you've changed APIs, update the documentation**.
5.  **Make sure the test suite passes**.
6.  **Commit your changes** with a descriptive commit message.
7.  **Submit a pull request**.

## Styleguides

### Git Commit Messages

- Use the present tense ("Add feature" not "Added feature")
- Use the imperative mood ("Move cursor to..." not "Moves cursor to...")
- Limit the first line to 72 characters or less
- Reference issues and pull requests liberally after the first line

### Coding Standards

- We use **TypeScript** for everything.
- Follow the existing code structure and naming conventions.
- Use **Prettier** and **ESLint** to format and lint your code before committing.
- Ensure all new components are responsive and follow the design aesthetic of the project.
